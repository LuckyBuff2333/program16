2.1 手机无法扫描或连接车机热点
TAG: LocalSend-BaseLocalActivity, LocalSend-ApRepository, SoftApManager, WifiService, GMWlanServiceImpl
- 观察日志：
  - BaseLocalActivity 是否有 configureFlutterEngine / onCreate / initSendContainer 相关日志。
  - LocalSend-ShareDeviceLayout 是否有 showQRCode / hideLoadingView。
  - SoftApManager 是否有热点启动和客户端变化日志（The connected wifi stations have changed with count: X）。
  - WifiService 是否有 registerSoftApCallback。
  - LocalSend-ApRepository 是否有 registerSoftApCallback() 及后续 onConnectedClientsChanged 日志。
- 排查步骤：
  1. 若 BaseLocalActivity 日志缺失，先确认入口是否真正拉起（可能是入口被 AMS/权限限制拦截，二维码自然无法展示，也就谈不上扫码连接）。
  2. 若二维码展示正常（有 showQRCode），但系统侧 SoftApManager / WifiService 完全没有热点启动与客户端变化日志，优先排查热点配置和系统网络策略（是否允许应用拉起热点、是否存在频繁启停被限制）。
  3. 若系统侧有 registerSoftApCallback / connected wifi stations have changed，但 LocalSend-ApRepository 只有 registerSoftApCallback() 错误日志、缺少 onConnectedClientsChanged，重点排查回调注册是否异常（权限、UID、不一致的接口签名），以及是否有重试逻辑。
  4. 若系统层和 LocalSend-ApRepository 的连接数日志都正常，但实际手机无法连上热点，则需要结合设备侧日志与信道质量，进一步排查信号/加密方式/频段等网络层问题。
2.2 已连接后不显示可用设备 / 无法建立会话
TAG: LocalSend-ApRepository, LocalSend-ShareDeviceLayout, SoftApManager, GMWlanServiceImpl
- 观察日志：
  - SoftApManager 是否有 The connected wifi stations have changed with count: 1/...。
  - GMWlanServiceImpl: onConnectedClientsChanged: [...] 是否正常输出（列表中是否有实际设备）。
  - LocalSend-ApRepository 是否有 onConnectedClientsChanged mConnectedDevicesCount =1 / N。
  - LocalSend-ShareDeviceLayout 是否有 updateDeviceList size = X、hideLoadingView、显示设备列表相关日志。
- 排查步骤：
  1. 若系统侧 SoftApManager / GMWlanServiceImpl 已经能看到客户端列表（count=1，onConnectedClientsChanged: [device_xxx]），但 LocalSend-ApRepository 完全没有 onConnectedClientsChanged 日志，只存在 registerSoftApCallback() 调用或错误日志，则问题大概率在 LocalSend 与 WifiService 的回调注册/绑定上。
  2. 若 LocalSend-ApRepository 的 mConnectedDevicesCount 已经从 0 变为 1 / N，但 LocalSend-ShareDeviceLayout 没有任何设备列表刷新日志（updateDeviceList size = X），需要排查数据流转：ApRepository 的状态是否正确通知到前端（LiveData/回调）、UI 是否持有正确的订阅。
  3. 若 ShareDeviceLayout 有 updateDeviceList size = X 日志，但前端仍显示“无设备”或无法点击建立会话，需要排查 UI 层：
    - 列表适配器是否正确绑定数据。
    - 是否存在被其他状态（loading/错误态视图）覆盖的情况。
    - 点击行为是否被其他手势/遮罩拦截。
2.3 传输过程中频繁断开 / 失败
TAG: LocalSend-ApRepository, LocalSend-ShareDeviceLayout, SoftApManager, NetWorkUtils（如有）
- 观察日志：
  - 一段时间窗口内，SoftApManager / GMWlanServiceImpl 的客户端连接数是否在 0 与 1 / N 之间频繁震荡。
  - LocalSend-ApRepository 的 onConnectedClientsChanged mConnectedDevicesCount 是否频繁在 0 与 1 之间切换。
  - LocalSend-ShareDeviceLayout 是否多次触发 updateDeviceList / startTransfer / 失败重试相关日志。
  - 是否存在网络工具类（如 NetWorkUtils）输出的网络质量或链路抖动日志。
- 排查步骤：
  1. 若系统层连接数本身就频繁变化（SoftApManager count 在 0 与 1 之间切换），说明链路物理/协议层不稳定，需要重点排查热点功率、干扰、功耗策略（休眠/节电）以及手机侧的漫游/切网行为。
  2. 若系统层连接数相对稳定，但 LocalSend-ApRepository 中 mConnectedDevicesCount 变化异常（时而 0、时而 1），需确认回调实现是否有去抖、是否存在误判（例如出现短暂的空列表就立即认为断开）。
  3. 若 ApRepository 的连接数日志稳定，但 ShareDeviceLayout 在传输过程中仍频繁重置列表或退出会话，需要结合前端日志确认：
    - 是否有主动中断逻辑（超时、错误码触发的中断）。
    - 是否存在 UI 层错误处理将“单次请求失败”误当作“会话结束”。
    - 是否有多入口同时操作同一会话导致状态互相覆盖。
