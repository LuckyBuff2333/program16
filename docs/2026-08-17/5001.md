# Bug 5001 日志分析报告

## 根因结论
慢查询长时间占用数据库连接未释放，导致连接池耗尽引发服务雪崩。

## 问题触发时间
2026-08-10 09:15:01

## 关键日志依据
- 2026-08-10 09:15:01 [ERROR] order-service - 获取数据库连接超时（等待 5000ms），连接池已耗尽，active=50 idle=0
- 2026-08-10 09:15:06 [ERROR] order-service - 下单接口 /api/order/create 批量超时，失败率 87%，根因指向数据库连接池耗尽
- 2026-08-10 09:25:33 [INFO] order-service - 慢查询扫描：SELECT * FROM t_order_detail WHERE status=0 执行耗时 28.4s，占用连接未释放

## 分析步骤
1. **发现问题现象**：order-service下单接口出现批量超时，失败率飙升至87%，同时user-service日志显示数据库连接等待时间异常升高，呈现跨服务资源争抢的扩散态势。
2. **深入排查过程**：按时间轴回溯，09:14:38起order-service连续报出连接等待时间警告，活跃连接数迅速逼近上限（48/50），随后在09:15:01正式抛出HikariPool连接获取超时异常，确认连接池已彻底枯竭。
3. **定位具体根因**：结合慢查询扫描日志锁定元凶，一条无索引的全表扫描SQL（`SELECT * FROM t_order_detail WHERE status=0`）执行耗时达28.4秒且事务未正常结束，持续占满全部50个连接池槽位，直接切断后续请求的资源供给。
4. **修复措施或建议**：立即Kill阻塞会话恢复服务；后续需为该SQL补充状态索引并限制返回字段，配置HikariCP连接泄漏检测与合理超时策略，上线慢SQL自动拦截、连接池监控看板及下游服务熔断降级机制。
