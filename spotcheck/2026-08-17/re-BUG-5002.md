# Bug BUG-5002 日志分析报告

## 根因结论
订单导出缓存OrderExportCache未释放导致JVM内存泄漏并引发OOM。

## 问题触发时间
2026-08-11 14:32:02

## 关键日志依据
- 2026-08-11 14:20:33 [WARN] order-service - JVM 老年代使用率 91%，Full GC 耗时 1.8s，存在内存泄漏迹象
- 2026-08-11 14:30:41 [ERROR] order-service - Full GC 耗时 6.2s，老年代回收率不足 5%，堆内存持续增长无法回收
- 2026-08-11 14:31:55 [ERROR] order-service - 大对象缓存 OrderExportCache 持有 240 万条记录未释放，确认为内存泄漏点
- 2026-08-11 14:32:02 [ERROR] order-service - java.lang.OutOfMemoryError: Java heap space，进程触发 OOM 自动重启

## 分析步骤
1. 发现的问题现象：14:10起order-service服务JVM老年代使用率持续攀升至91%，伴随Full GC耗时剧增（1.8s至6.2s）且回收率极低，最终于14:32抛出OOM异常并触发K8s Pod自动重启。
2. 深入排查的过程：结合日志时间线梳理内存恶化轨迹，发现14:05启动的“订单导出任务”与内存异常爆发高度吻合；通过日志中的内存诊断信息锁定具体泄漏组件为`OrderExportCache`。
3. 定位到的具体根因：订单导出任务生成的超大对象缓存`OrderExportCache`在业务执行完毕后缺乏清理机制，长期驻留堆内存并累积约240万条无效记录，直接耗尽Java堆空间。
4. 修复措施或建议：立即修复导出模块缓存的生命周期管理代码，确保任务结束后主动释放引用；引入缓存容量限制与TTL过期策略，并对大对象导出改为流式分批处理，同时完善JVM内存水位监控告警。
