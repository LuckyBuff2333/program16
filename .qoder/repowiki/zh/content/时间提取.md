# 触发时间提取

## 引用文件
- `src/api/routes/trigger.py` — 触发时间 API 路由
- `src/services/trigger_ops.py` — 触发时间云端操作（读写、再平衡）
- `src/services/trigger_service.py` — 触发时间提取服务
- `src/clients/jira_client.py` — 从 Jira 提取触发时间的函数
- `src/web/server.py` — 诊断验证逻辑（`_diag_verify_suggestion`）
- `src/services/server_legacy.py` — 视频/图片 OCR 提取

详细文档见 `timestudy/` 目录。

---

## 提取优先级链

```
标题/字段 → 评论区文本 → 描述文本 → 附件文件名(.log/.mp4) → gmlogger包内 → 视频OCR → 评论区main.log附件名(兜底)
```

## 批量提取流程

```
日志附件检测(_has_gmlogger_logs)
  → 无: 跳过(no_gmlogger)
  → 有: 按模式执行
    → 视频优先: 视频帧OCR → 评论/文本 → 图片OCR兜底
    → 文本优先: 评论/文本 → 视频帧OCR → 图片OCR兜底
```

## 视频帧 OCR 逻辑

- 截帧: 0s / 1s / 3s / 6s
- ref_pool 验证: 包内 main.log 时间(权威,容差5min) > 外层 gmlogger 文件名时间(补充,容差10min)
- 未命中时: 12h 转换 / 文件名回退 / 图片附件 OCR 兜底

## 评论区附件名时间提取（兜底）

- 仅匹配 `main.log_YYYY_MM_DD_H_M_S` 格式
- 分钟频率统计策略: 统计各分钟出现次数 → 筛选 >= max(2, max_count//2) → 取中位数
- 仅在视频/图片/gmlogger 均未提取到时启用

## 云端触发时间管理

- 飞书多维表格存储，每表 500 条上限
- 写入策略: 按剩余空间降序，优先填空位最多的表
- 再平衡: `POST /api/trigger_time/rebalance`，将超限表多余记录搬入余量最大的未满表

## OCR 引擎

- 优先 RapidOCR (box_thresh=0.3, text_score=0.15)
- RapidOCR 无结果或置信度<0.3 时回退 EasyOCR
- 延迟初始化: 仅在需要时才加载模型
- 类型安全: conf 字段强制转 float
