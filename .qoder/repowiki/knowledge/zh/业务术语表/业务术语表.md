### Bug 文档沉淀工具
- 定义：本项目名称，指基于 AI 日志分析工具的 Bug 文档沉淀与故障分析闭环工具，实现 bugid 去重、AI 分析生成文档、Jira 报错原因/评论比对、每日结论报表、知识库手工入库及随机抽查复核的完整流程。

### bug_records 表
- 定义：数据库中用于存放已有 bugid 的表名，工具仅对其进行只读比对以实现 bugid 去重，表数据由外部维护，工具不向其写入任何数据。

### analyze
- 定义：CLI 主命令，执行 bugid 去重 → AI 日志分析 → Jira 报错原因/评论比对 → 生成 docs 与 reports 下的每日 CSV 结论报表，不写数据库。
- 别名：分析

### retry
- 定义：CLI 命令，对分析失败的 bug 重新执行分析流程，直至分析正确；结果覆盖更新当日结论报表。
- 别名：重试

### store
- 定义：CLI 命令，开发确认分析正确后手工执行，将对应 bug 的分析文档推入知识库接口；工具不做自动拦截校验，是否入库由执行人自行判断。
- 别名：入库、知识入库

### report
- 定义：CLI 命令，查看当日（或指定日期）结论报表路径，报表由 analyze/retry 自动生成，包含 bugid、触发时间、根因相似度、流程相似度等列。
- 别名：报表

### audit
- 定义：CLI 命令，从数据库已入库表随机抽取 N 个 bugid（默认 30，排除历史已抽查过的），带触发时间重新调用 AI 分析工具，新结果与库中存储的根因分析/分析流程字段做相似性对比，生成 `reports/audit_comparison.csv` 供人工审核；每次抽查的 bugid 追加记录到 `reports/audited_bugids.csv`。
- 别名：随机抽查、抽查复核

### 每日结论报表
- 定义：analyze/retry 运行后生成的 `reports/YYYY-MM-DD_daily.csv`，包含每条 bug 的分析结论、相似度指标与文档路径；同日多次运行按 bugid 覆盖合并，不产生重复行。
- 别名：日报、CSV 报表

### 审核表格
- 定义：`reports/audit_comparison.csv`，audit 命令产出的随机抽查对比表，包含 bugid、触发时间、新根因结论、已入库根因分析、根因相似度、已入库分析流程、流程相似度、文档路径、抽查时间及人工审核结论列，供人工审核后回填。
- 别名：audit_comparison.csv、抽查对比表

### 已抽查记录
- 定义：`reports/audited_bugids.csv`，记录每次 audit 抽查过的 bugid 及抽查时间，下次执行时自动排除这些 bugid，避免重复抽查。
- 别名：audited_bugids.csv、抽查记录

### Agent 过滤
- 定义：对 Jira 评论区评论进行处理的逻辑，将原始评论过滤为可用于日志分析的步骤信息，再参与与文档分析步骤的相似性比对；当前预留 LLM 占位，可通过 `core/filter.py` 的 `_agent_filter` 替换。
- 别名：评论过滤、filter

### 相似性比对
- 定义：对分析结果的双重比对机制：根因层面用关键词命中比例（`root_cause_hit_ratio` 阈值）判定，步骤层面用 TF-IDF 余弦相似度（`threshold` 阈值）判定；两者均达标才视为分析正确。
- 别名：相似度比对、双重比对

### mock 模式
- 定义：三个外部接口（AI 日志分析、Jira、知识库）的统一开关，`mock: true` 时使用内置样例数据便于本地验证，接入真实环境时改为 `false` 并填写对应 url 与字段映射。
- 别名：mock、模拟模式
