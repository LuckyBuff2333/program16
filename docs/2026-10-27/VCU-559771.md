1 背景简介

本文档针对 Cluster（仪表盘）系统的 Cluster HMI 层代码进行日志解析说明，严格限定在 Cluster 目录下的 src/hmi/（HMI 入口与 Kanzi 渲染线程）和 src/uxlogic/（UX 逻辑层）两部分代码。

1.1 日志查看方式

- QNX 平台：通过 gmlog / dlt_raw 工具查看日志
- 日志过滤：使用日志 TAG 关键字搜索定位问题
- ###Fatal### 标记：所有带此标记的日志表示关键状态或严重异常，是排查的首要目标

2.2 Kanzi UI 窗口创建异常

Kanzi 渲染线程（cluster_hmiapp_kanzi_thread）在 QNX 平台上创建 Screen 窗口时，如果系统资源不足或配置错误，会导致窗口创建失败。

日志TAG

screen_create_window | SCREEN_PROPERTY | ###Fatal###

特征日志

正常日志：
Screen Alpha mode is set to 1
Screen Sensitivity is set to 1

异常日志：
screen_create_window failed ###Fatal###
Could not get SCREEN_PROPERTY_DISPLAY_COUNT. ###Fatal###
Failed to set SCREEN_PROPERTY_DISPLAY. ###Fatal###
Failed to set SCREEN_PROPERTY_PIPELINE. ###Fatal###
Failed to set SCREEN_PROPERTY_ZORDER. ###Fatal###
Failed to set SCREEN_PROPERTY_SIZE. ###Fatal###
Failed to set SCREEN_PROPERTY_POSITION. ###Fatal###
Failed to set SCREEN_PROPERTY_BUFFER_SIZE. ###Fatal###
Failed to set SCREEN_PROPERTY_GLOBAL_ALPHA. ###Fatal###
Failed to set SCREEN_PROPERTY_TRANSPARENCY. ###Fatal###
screen_share_window_buffers returned: -1 ###Fatal###
create second window ###Fatal###
Unable to get QNX graphics output. ###Fatal###

分析方法

窗口创建异常通常与 QNX Screen 系统状态有关。排查步骤：
1. 检查 Display 是否可用（DISPLAY_COUNT）
2. 检查 Pipeline 分配是否冲突
3. 检查窗口属性设置是否返回错误码
4. 如果是 create second window 失败，说明双窗口模式下第二个窗口分配失败

3.1 布局模式与视图切换异常

布局模块负责管理仪表的视图模式（V/MAX/Normal/ADAS 等）和区域显示逻辑。

日志TAG

[Layout] | [layout_logic] | CurrentLayout | [MapDisplayJudgment]

特征日志

正常日志：
[layout_logic]P_ADAS_DISPLAY_PRESENT = 1
[Layout] ADAS_Configuration_Type is 1
[Layout] GearType = 1, SREnable = 0, CurrentView = V, isViewChangeValid = 1
[Layout] internalIsSmallPeekinDisplay = 0, internalSetScreenOff = 0, VModeState = 0, NaviConnectionStatus = 1, CarPlayConnectionStatus = 0, OffViewDisplay = 0, Navi_CurrentView = map_local
