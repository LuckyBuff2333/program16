# ADP 接口问题判别与处理策略

> 代码位置：`src/services/adp_ops.py`  
> 最后更新：2026-11-05

## 一、错误码四级分类与处理策略

ADP v2 Chat 接口返回的错误码（SSE `error` 事件中的 `Error.Code`）分为四类，每类处理策略不同：

### 1. 致命错误（Fatal）→ 立即终止

配置/账号级问题，发"继续"无效，必须修复配置后才能恢复。

| 错误码 | 含义 | 处理 |
|--------|------|------|
| `4505004` | AppKey 无效 | 检查 config.yaml 的 adp.app_key |
| `460001` | Token 校验失败 | 检查密钥是否正确 |
| `460004` | 应用不存在 | 检查应用是否已创建 |
| `460026` | 应用停用或欠费 | 联系平台管理员 |
| `460048` | 应用未发布 | 在 ADP 控制台发布应用 |
| `460501` | 输入内容安全拦截 | 检查输入内容 |
| `460032` | 模型余额不足 | 充值或切换模型 |
| `460702` | 专属模型余额不足 | 充值专属模型额度 |

**代码常量**：`FATAL_ERROR_CODES`  
**处理逻辑**：SSE 收到 error 事件 → break 终止流 → `run_adp_single` early return → 标记"分析失败"  
**归因格式**：`ADP平台配置错误: {含义}({错误码})`

---

### 2. 限流错误（Rate Limit）→ 退避后重发原始请求

并发/容量超限，等待后重发即可恢复。

| 错误码 | 含义 | 退避时间 |
|--------|------|----------|
| `460011` | QPM 并发超限 | 60s |
| `460031` | 并发限流 | 60s |
| `460711` | 空间级 TPM 限流 | 60s |
| `460712` | 空间级 QPM 限流 | 300s |
| `460713` | 空间级 RPM 限流 | 300s |
| `460721` | 应用级 TPM 限流 | 60s |
| `460701` | 企业级 TPM 限流（实测日志出现） | 60s |
| `460722` | 应用级 QPM 限流 | 300s |
| `460723` | 应用级 RPM 限流 | 300s |

**代码常量**：`RATE_LIMIT_CODES`（并发）+ `CAPACITY_LIMIT_CODES`（容量）  
**处理逻辑**：SSE break → 续接机制 `need_resend` → 退避等待 → 重发原始消息（复用原会话 ID）  
**归因格式**：`ADP并发限流({错误码})` 或 `ADP容量限流({错误码})`

---

### 3. 可重试错误（Retryable）→ 发"继续"续接

模型侧临时问题，发"继续"即可恢复分析。

| 错误码 | 含义 | 处理 |
|--------|------|------|
| `460020` | 模型超时 | 发"继续"恢复分析 |
| `460030` | 模型服务异常 | 发"继续"恢复分析 |

**代码常量**：`RETRYABLE_ERROR_CODES`  
**处理逻辑**：SSE break → 续接机制 `need_continue`（含 `err_code in RETRYABLE_ERROR_CODES`）→ 发"继续"  
**归因格式**：`ADP模型超时({错误码})`

---

### 3b. 输出内容安全拦截（460502）→ 同会话发脱敏继续指令

平台对 Agent 输出做内容安全审核，命中敏感词/风控会返回 `460502`。  
该错误**不是永久失败**：LLM 每次生成话术不同，原请求重试或发脱敏指令通常可以恢复。

| 错误码 | 含义 | 处理 |
|--------|------|------|
| `460502` | 输出内容安全拦截 | 同会话发脱敏继续指令；最多 2 次 |

**代码常量**：`CONTENT_SAFETY_CODES` + `CONTENT_SAFETY_CONTINUE_PROMPT`  
**处理逻辑**：

1. 首轮返回 460502 → 复用原会话，发送 `CONTENT_SAFETY_CONTINUE_PROMPT`，最多 2 次；
2. 续接循环中再次 460502 → 继续发脱敏指令，累计最多 2 次；
3. 仍失败 → 归因 `输出内容安全拦截(460502，已重试2次)`，不再无限续接。

**脱敏指令内容**：

> 上一条输出被平台内容安全策略拦截，请继续完成分析，不要重复输出被拦截的原文。  
> 只输出脱敏结论，不要输出完整 VIN、手机号、账号、Token、Cookie、SN、地址等敏感信息。  
> 如需引用日志，只保留字段名、行号、模块、时间和 traceid，敏感值用 `***` 代替。  
> 输出：结论、根因、影响模块、触发条件、修复建议，并生成 HTML 报告。

**归因格式**：`输出内容安全拦截(460502，可脱敏续接)`

---

### 4. 需人工干预错误（Manual Intervention）→ 换新会话 ID 重试

会话级冲突，换新 ID 即可解决。

| 错误码 | 含义 | 处理 |
|--------|------|------|
| `460919` | 会话 ID 已存在 | 生成新 ConversationId 重试 |

**代码常量**：`SESSION_CONFLICT_CODES`  
**处理逻辑**：SSE break → 续接机制 `need_new_session` → 生成新 `uuid4().hex[:32]` → 用新 ID 重发原始消息  
**归因格式**：`ADP会话冲突({错误码})`

## 二、ReplyMethod 判别

`response.completed` 事件的 `ExtraInfo.ReplyMethod` 是判断分析结果的关键信号：

| ReplyMethod | 含义 | 处理策略 |
|-------------|------|----------|
| `1` | 正常回复 | 正常提取报告 |
| `12` | 正常回复（变体） | 正常提取报告 |
| `18` | 正常回复（变体） | 正常提取报告 |
| `3` | 拒答 | 停止续接，归因为"智能体收口无报告" |
| `7` | 并发超限 | 归因为"ADP并发超限(ReplyMethod=7)" |
| `15` | 澄清确认（等用户补充信息） | 停止续接，归因为"智能体收口无报告" |

**代码常量**：
- `NO_REPORT_REPLY_METHODS = {"3", "15"}` — 拒答/澄清
- `CONCURRENT_LIMIT_REPLY = "7"` — 并发超限

## 三、续接机制（Step 3.3）

当分析结果不满足预期时，自动触发续接，最多 2 轮：

```
触发条件                          → 动作
─────────────────────────────────────────────────────
完成状态=分析失败 + 归因="分析完成但未产出HTML报告"  → 发"继续"
_looks_truncated(full_text)     → 发"继续"
err_code ∈ RETRYABLE_ERROR_CODES   → 发"继续"
err_code ∈ RATE_LIMIT_CODES     → 退避60s/300s → 重发原始消息
无 full_text + request_ack + 无 stream_exc → 重发原始消息
err_code ∈ SESSION_CONFLICT_CODES   → 换新会话ID → 重发原始消息
```

**合并策略**：
- 续接返回的文本追加到 `full_text`
- 续接返回的 `file_urls` 追加到已有列表
- 重新调用 `extract_adp_results()` 提取结果
- 任一轮获得报告 URL 或完成状态为"完成"则停止

## 五、报告链接提取优先级（_extract_report_url）

**核心原则：签名 URL 始终优先于无签名 URL，避免 COS 403 Forbidden。**

| 优先级 | 来源 | 特征 | 说明 |
|--------|------|------|------|
| 1a | reply 文本 | `agent.adp-cos.com` + 含 `q-sign` | 最可靠，签名有效 |
| 2 | reply 文本 | `lke.cloud.tencent.com/s/xxx` | 短链，302 → COS 签名 URL |
| 3a | file_urls | `content.added` 事件 + 含 `q-sign` | SSE 流中捕获的签名 URL |
| 3b | file_urls | `content.added` 事件 + 无签名 | 降级使用 |
| 1b | reply 文本 | `agent.adp-cos.com` + 无签名 | 最后兜底（可能 403） |
| 4a | reply 文本 | `sandbox.adp.cloud.tencent.com` | 沙箱 URL（401 不可下载，仅展示） |
| 4b | reply 文本 | `/workdir/case_.../out/report_...html` | 沙箱路径（拼接为 4a 格式） |

### 签名 URL 判断标准

URL 的 query 参数中包含 `q-sign` 相关字段即为签名 URL：

```
?q-sign-algorithm=sha1
&q-ak=AKIDxxx
&q-sign-time=xxx
&q-signature=xxx
```

无签名的裸路径（如 `https://agent.adp-cos.com/agent-app/.../report_xxx.html`）会被 COS CDN 拒绝返回 **403 Forbidden**。

### 已知陷阱

- ADP 智能体有时在 reply 文本中只放**无签名的裸路径 URL**，但 `content.added` 事件的 `file_urls` 中有带签名的正确 URL
- 旧代码用 `re.search` 匹配到第一个就 return，导致拿到无签名 URL → 403
- 修复后扫描所有匹配，按签名优先排序，确保拿到可用的签名 URL

## 六、辅助判别信号

### Content.Type 信号

| Type | 含义 | 处理 |
|------|------|------|
| `file` | 文件产物 | 收集到 file_urls |
| `option_cards` | 追问卡片 | 标记 has_cards，发"继续"无效 |
| `questionnaire` | 问卷 | 标记 has_cards，发"继续"无效 |

### 文本形态判断

| 函数 | 条件 | 判定 |
|------|------|------|
| `_looks_truncated` | ≥2000字 + 无收尾章节 + 非终止符结尾 | 疑似截断，发"继续" |
| `_looks_like_clarify_or_refusal` | ReplyMethod=3/15 或关键词命中 | 拒答/澄清，停止续接 |
| `_looks_complete_no_report` | ≥800字 + ≥2个收尾章节标志 | 主体完整但缺报告 |

### 澄清/拒答关键词

**澄清类**：请提供、请补充、请上传、请确认、无法下载、无法获取、缺少日志…  
**拒答类**：无法分析、无法处理、不能分析、拒绝回答、不予回答

## 七、附件接口异常与“无日志附件”的区分（2026-10-29）

`query_attachments()` 的返回值语义：

| 返回 | 含义 | 状态 | 是否重试 |
|---|---|---|---|
| `list`（非空） | 正常 | 继续分析 | — |
| `list`（空） | 接口正常但确实没有附件 | `无法分析`（无日志附件） | ❌ 不重试，直接下一条 |
| `None` | 接口异常（非 JSON / HTTP 5xx / 重试后仍失败） | `分析失败`（ADP附件接口异常） | 本项不重试，可下次重跑 |

> 背景：2026-10-29 19:14 出现过 `resp.json()` 抛 “Expecting value: line 1 column 1 (char 0)”，
> 原因是 dpportal 在 DNS/网关抖动时返回了空响应/HTML；旧逻辑会把它误判成“无附件 → 无法分析”。
> 同一时段 `getaddrinfo failed` 属于 DNS 解析失败，不是 TPM 限流；真正的 TPM 墙会在 SSE 里返回 `4607xx` 错误码。

> 注：**TPM 墙（460701/460711/460721）退避 60s**；QPM/RPM（460712/460713/460722/460723）仍退避 300s。

## 八、ADP 分析结果误判与处理（2026-11-01）

### 8.1 三类“没出报告”要分开

| 类型 | 判定依据 | 处理动作 | 会话 |
|---|---|---|---|
| **流中断（工具调用截断）** | 结尾卡在半截标签（`</inv`、`</param`）、`<invoke>/<parameter>` 不成对 | 发“继续”，复用原会话；连续 2 轮新增 <200 字且仍截断 → 改发“停止继续取证，直接输出最终结论和 HTML 报告” | 同一个 ConversationId |
| **智能体收口无报告** | 文本含“没有可推进/分析完成/无更多工作/请给新指令”等收口话术，且无报告链接 | **不发“继续”**，改发定向请求：`请把当前结论生成 HTML 分析报告，并给出下载链接`；仍无报告则归因“智能体收口无报告” | 同一个 ConversationId |
| **ADP 无返回** | 整个流 0 字符 | 不立即判网络异常；标记 `ADP 无返回`，等本轮全部任务跑完后**统一重试一次** | 重试是新一轮，**新 ConversationId** |

### 8.2 追问（questionnaire / option_cards）

| 轮次 | 判定 | 动作 | 会话 |
|---|---|---|---|
| 第 1 次 | SSE `content.added` 的 `Content.Type` 为 `questionnaire` 或 `option_cards` | 自动回复：`按现有描述和附件继续分析，不需要澄清，直接输出最终结论和 HTML 报告` | 同一个 ConversationId |
| 同一轮再次追问 | 自动应答后仍收到追问信号 | 停止，归因 `需要澄清（ADP智能体追问，需人工作答）` | — |

- 自动应答**每条 Jira 仅一次**；
- 续接后会同步 `has_cards/questionnaire/reply_method`，避免上一轮标记残留；
- 总续接轮数上限仍为 6。

### 8.3 澄清/拒答

| 信号 | 判定 | 动作 |
|---|---|---|
| `ReplyMethod=15` | 智能体在等用户补充 | 不发“继续”，归因澄清类 |
| `ReplyMethod=3` | 智能体拒答 | 不发“继续”，归因拒答 |
| 文本澄清关键词（请提供/请补充…） | 短文本澄清 | 不发“继续” |
| `ReplyMethod=7` | 并发超限 | 归因并发超限 |

### 8.4 错误码与动作

| 类型 | 错误码 | 动作 | 是否续接 |
|---|---|---|---|
| 致命 | 4505004/460001/460004/460026/460048/460501/460032/460702 | 立即终止 | ❌ |
| 输出内容安全 | 460502 | 同会话发脱敏继续指令，最多 2 次 | ✅（脱敏） |
| 可重试 | 460020/460030 | 发“继续” | ✅ |
| 并发限流 | 460011/460031 | 退避 60s 后重发原消息 | ❌ |
| TPM | 460701/460711/460721 | 退避 60s 后重发原消息 | ❌ |
| QPM/RPM | 460712/460713/460722/460723 | 退避 300s 后重发原消息 | ❌ |
| 会话冲突 | 460919 | **换新 ConversationId** 重发原消息 | 新会话 |

> 460502 输出内容安全拦截：已改为**自动脱敏续接**，最多 2 次；仍失败才标“分析失败”。

## 九、会话 ID 使用规则

| 场景 | ConversationId | 说明 |
|---|---|---|
| 首次分析 | 新生成 | 从 `response.created` 捕获 `Response.ConversationId` |
| 发“继续” | **复用同一个** | `signal_info.conversation_id` |
| 自动应答追问 | **复用同一个** | 同上 |
| 限流后重发原消息 | **复用同一个** | 保留上下文 |
| 会话冲突 460919 | **新建** | 平台要求换会话 |
| 空返回末尾重试 | **新建** | 重新调用 `run_adp_single`，视为新任务 |
| 截断换策略（直接出报告） | **复用同一个** | 仍在原会话内 |

补充：

- `TraceId` 是**请求级**，每次响应都会变；同一会话内也会变；
- `traceid` 字段取**最后一次**响应的 TraceId；
- 失败时不写 `traceid`。

## 十、时间提取与诊断的误判处理

### 10.1 提取优先级

| 场景 | 优先级 |
|---|---|
| **Closed** 问题 | 最新“结论/日志”评论中**日志语句靠后的时间**；无日志语句取通用文本靠后时间 |
| 非 Closed 问题 | 视频 + gmlogger 提取优先；无结果再走标准提取/图片 OCR |

### 10.2 关键防误判规则

| 规则 | 作用 |
|---|---|
| 视频时间不得覆盖“贴近抓包”的结果 | 防止晚录视频把正确时间改晚 |
| 提取晚于抓包 >45 分钟 | 回退抓包时间/邻近视频时间 |
| 晚于 Jira 创建且无参照 | 回退创建前 5 分钟 |
| 无抓包且偏离创建 >3 天 | 回退创建前 5 分钟 |
| gmlog 包名无时间 | 用**视频文件名时间**兜底，并补齐日期 |
| 日志包识别 | 兼容 `gmlogger/gmlog/GMLog/log_/logs.zip/pataclogger` |

### 10.3 诊断状态

| 状态 | 含义 | 处理 |
|---|---|---|
| 正常 | 当前时间 ≈ 抓包/视频参考（容差内） | 无需修改 |
| 待确认 | 与参考有偏差但在可接受窗口 | 人工确认 |
| 不可用 | 晚于抓包 >5 分钟，或早于抓包 >60 分钟 | 建议替换为参考时间 |
| 无参考 | 无 gmlog/视频/评论可用时间 | 用视频文件名兜底；仍无则人工 |

## 十一、失败分类、写回与重试

### 11.1 失败分类（写入 `分析失败归因`）

```
流中断（工具调用截断）
智能体收口无报告
ADP 无返回
需要澄清（ADP智能体追问，需人工作答）
ADP附件接口异常
无日志附件
ADP平台配置错误 / 平台限流 / 网络异常 …
```

### 11.2 写回规则

| 场景 | `分析失败归因` | `原因` | `traceid` |
|---|---|---|---|
| 成功 | 空 | 空 | 最后一次 TraceId |
| 失败 | 本次最新原因 | 最新短分类（澄清/截断/超时等） | 不写 |

- 重复失败时**始终用本次原因覆盖**，不保留旧值；
- 失败不写 `traceid`，避免误导。

### 11.3 重试与修复

| 机制 | 说明 |
|---|---|
| 空返回末尾重试 | 本轮全部任务结束后统一重试一次 |
| 截断续接 | 最多 6 轮“继续”，无进展自动切换“直接出报告” |
| 追问自动应答 | 每条一次 |
| 460502 脱敏续接 | 首轮 + 续接累计最多 2 次脱敏指令 |
| 失败原因覆盖 | 每次失败写最新原因 |
| trace 技能返回值 | 早退分支统一返回 3 元组，避免成功被误判失败 |
| 460502 输出内容安全拦截 | 同会话发脱敏继续指令，最多 2 次；仍失败才标记分析失败 |
