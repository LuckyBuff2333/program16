## 分析结论

- **根因**: INC 亮度条控件 `PatacVerticalSeekBar`（`app:id/inc_brightness_bar`）的拖动调节走的是 SeekBar 触摸回调路径（`dispatchTouchEvent` → `onStartTrackingTouch`/`onStopTrackingTouch` → `changeProgress`），**该路径不经过 `View.performClick`，因此不触发 SystemUI 的按键音框架（`ViewRootImpl.shouldMute` → `AudioManager.playSoundEffect`）**。控件在拖动/进度变化时未显式调用 `playSoundEffect(SoundEffectConstants.CLICK)`，导致调节亮度条全程无按键音。

- **因果链**: 
  `PatacVerticalSeekBar` 拖动 → 走 SeekBar 触摸回调（非 performClick）→ 无 `shouldMute` 判断 → 无 `playSoundEffect` 调用 → 无按键音请求发出 → 音频系统无音可放 → 用户感知"调节亮度条无按键音"。
  同时亮度功能正常（`setDisplayBrightness` 成功，duration=3ms），说明仅音效逻辑缺失，非功能故障。

- **关键证据**:
  - 拖动时段（14:23:34~14:24:43）PID 2027 **完全无** `AudioManager`/`playSoundEffect`/`shouldMute` 调用（强负向证据）

  - 对比基线：QS 点击时段（14:22:50~14:22:54）有 `AudioManager playSoundEffect effectType:0,userId:-2`
  - `PatacVerticalSeekBar` 日志仅有 `moveTime/moveY` 与 `dispatchTouchEvent`，无任何音效日志、无 `onProgressChanged`
