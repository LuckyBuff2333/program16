# 背景

常见定位问题从表现形式上来讲包含车标**漂移**、**超前**、**滞后**、**卡顿**、**抖动**、**静止**，从根因上来讲主要分为几类：**GPS信号异常**、**IMU数据异常**、**脉冲车速数据异常**。

## GPS信号异常

GPS信号异常的情况多种多样，分析的时候需要需要从多个维度去排查，主要分为以下几类：

### GPS数据没有回调

### **星历数据异常**

GPS定位的原理大致可以理解为：通过测量你（接收器）到至少4颗卫星的距离，然后通过几何学交汇确定你的精确位置。为什么是四颗的原因是三颗得出经度、纬度和海拔，利用第四颗卫星来算出时间，这样GPS接收器就能同时计算出你的精确三维位置和精确的时间。

**异常日志**

1.[检查GPS数据是否正常回调]

2.[检查星历数据是否异常]

3.[检查GPS车速与脉冲车速差值是否过大]

4.[检查GPS数据上报频率是否异常]

5.[检查IMU数据是否异常]

6.[检查脉冲车速数据是否存在异常]

注：严格按照问题排查顺序来进行排查，当出现一个前置的问题后，后续的问题则不需要再进行分析，即分析到前置问题为止

## 分析结论
- **根因**: 路线规划页（RouteFragment）与备选充电站列表页（NewAlterChargeFragment）**均未实现/未注册"5min 无操作超时自动刷新提示"功能**。导航进程内不存在任何无操作检测逻辑、超时计时器、自动刷新数据请求或提示 UI 展示调用，导致停留超过 5min 后无任何提示。
- **因果链**: 功能未实现（无无操作检测 + 无超时计时器 + 无自动刷新 + 无提示 UI）→ 页面停留超时后无任何触发 → 用户看不到"将进行自动刷新"提示 → 表现为 Bug 描述的实际结果。
- **关键证据**:
  - 全量 474722 行搜索 `5min|300000|300s|超时|自动刷新|刷新|提示|Tip|Toast|Dialog` **零匹配**
  - 无 `onUserInteraction|Inactivity|Idle|无操作` 无操作检测日志（仅系统层 PowerManagerNotifier.onUserActivity，非导航业务）

  - `onSilentSearchResult`（MapModel.java:4154）为搜索业务回调（SearchType:3, taskId:10000190），非自动刷新机制
  - NewAlterChargeFragment 生命周期日志止于 onViewCreated end（13:13:22.385），此后无 onResume/数据刷新
