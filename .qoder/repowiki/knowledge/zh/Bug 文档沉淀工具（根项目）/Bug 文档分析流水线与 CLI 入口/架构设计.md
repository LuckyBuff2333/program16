模块由四个职责清晰的 Python 文件组成，形成「CLI → 流水线 → 外部客户端/核心逻辑 + 配置/DB」的分层结构：
- `main.py` 使用 argparse 定义 `analyze / retry / store / report / audit` 五个子命令，每个子命令对应一个 cmd_* 处理器，统一通过 `db.init_db()` 初始化后调用 `pipeline` 或 `core.audit` 完成业务。
- `pipeline.py` 是流程编排层，串联步骤1（`db.filter_new_bugids` 去重）、步骤2（`ai_log_client.analyze_logs` + `doc_generator.save_document` 生成文档）、步骤3（`jira_client` 提取报错原因与评论，经 `comment_filter` 过滤后用 `similarity.compare_root_cause` / `compare_steps` 双重比对），最终由 `report.generate_daily_csv` 输出当日 CSV 结论报表；失败单个 bug 不中断整体流程。
- `config.py` 集中加载 `config/config.yaml` 并缓存全局 `_CONFIG`，提供 `get_path` 自动创建输出目录和 `setup_logger` 按日期归档日志（控制台 + `logs/app_YYYY-MM-DD.log`）。
- `db.py` 基于 SQLAlchemy declarative 定义 `BugRecord` 表模型，但工具本身只进行只读查询：`filter_new_bugids` 用于步骤1去重，`fetch_audit_candidates` / `fetch_stored_analysis` 供审计抽查读取已入库知识库数据；SQLite URL 支持相对路径自动解析到项目根目录。
依赖方向单向：`main → pipeline → (clients, core, db)`，`db` 与 `config` 为底层基础设施，无反向依赖。
