# VCU-514916 评论分析总结

## 排查结论

已定位为ICM已知问题（修复版本v3.13.x），VCU未收到唤醒报文致无网，备车复测及蜂窝上游原因待进一步排查。


## 排查过程分析

### 问题现象
车辆从休眠唤醒后出现VCU无网报错，蜂窝网络验证失败导致DNS解析全面失败，远控服务及VCU通信链路（FDBUS）均无法建立，云端无法触达车辆。

### 排查结论
- **已确认的事实**：休眠期间网络断开属正常（`SLEEP(0)`状态）；VCU在唤醒后未收到唤醒报文，一直处于休眠状态；ICM存在已知问题，修复版本为v3.13.x。
- **尚未确认需进一步排查的方向**：备车团队复测结果待确认；蜂窝网络验证失败的上游原因（SIM卡状态、APN配置、信号强度）在日志中缺失，需补充排查。
- **与AI日志分析结论的一致点**：均确认蜂窝网络验证失败是根因，导致网络能力被移除（`NET_CAPABILITY_INVALIDATE`），进而引发DNS解析失败和远控服务无法建立。
- **与AI日志分析结论的差异点**：AI日志分析认为VCU通信链路（FDBUS）失败是蜂窝网络失败的直接后果，而Jira评论中更侧重于VCU未收到唤醒报文这一独立问题，两者在因果链的侧重点上存在差异。


## 时序排查详情

### AI日志分析

- 蜂窝网络验证失败是根因：ConnectivityService 在唤醒后约 16 秒判定 [100 CELLULAR] validation failed 并移除 VALIDATED 能力，可用网络数归零（L12037、L12038、L12060）
- DNS 解析全面失败是直接后果：四个 sgmlink.com 子域名全部无法解析，覆盖账号、采集、MQTT、远控 WebSocket 多个业务（L137、L11894、L13431、L15965）
- 远控服务 socket 从未建立：PatacRemoteService 的 socketFlag 从唤醒到再次休眠始终为 false，远控指令无下发通道（L2711、L29066）
- VCU 通信链路（FDBUS）在唤醒后 2ms 即失败：server offline 和 TCP 连接失败几乎与唤醒同时发生，说明 FDBUS 连接可能依赖蜂窝网络（L675、L677）
- 云端通信通道双重失败：CommProxy 报 onConnectFailure ###Fatal###，远控 WebSocket 心跳超时断开，云端侧无法触达车辆（L156、L12295）
- 9V002 错误码未在日志中定位：该错误码原文未出现在日志窗口内，具体产生代码路径未知
- 蜂窝网络验证失败的上游原因未体现：SIM 卡状态、APN 配置、信号强度等信息在日志窗口内缺失
