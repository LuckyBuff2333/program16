# 日志、配置与错误处理

公共后端基础设施，供所有模块使用。

## 引用文件
- `src/config.py` — 配置加载 + 日志初始化
- `src/clients/base.py` — HTTP 客户端基类
- `config/config.yaml` — 全局配置文件

---

## 1. 日志系统 (setup_logger)

**位置**：`src/config.py` → `setup_logger(name)`

- 每个模块通过 `setup_logger("模块名")` 获取 logger，命名空间隔离
- 双通道输出：控制台 StreamHandler + 按日归档文件 `logs/app_YYYY-MM-DD.log`
- 格式：`%(asctime)s [%(levelname)s] %(name)s - %(message)s`
- 幂等初始化：已添加 handler 的 logger 直接返回
- 全局默认 INFO 级别

**约定**：
- 所有模块必须通过 `setup_logger(name)` 获取 logger，禁止裸用 `logging.getLogger()`
- logger 名称遵循功能域粒度（main、pipeline、doc_gen、filter 等）

---

## 2. 配置系统 (load_config)

**位置**：`src/config.py` → `load_config()` / `get_path(key)`

- 单一配置源：`config/config.yaml`，PyYAML 加载
- 进程内单例缓存（`_CONFIG` 全局变量）
- `get_path(key)` 从 `output` 段取相对路径，拼接 PROJECT_ROOT 转绝对路径并确保目录存在

**配置结构**：
- `database.*` — 数据库连接与表名
- `ai_log_api.*` — AI 日志分析接口（mock/URL/超时/字段映射）
- `jira_api.*` — Jira REST API（mock/URL/超时/认证）
- `knowledge_base_api.*` — 知识库接口
- `similarity.*` — 相似度阈值
- `audit.*` — 抽查配置
- `output.*` — 输出目录（doc_dir/report_dir/log_dir）

---

## 3. HTTP 客户端基类

**位置**：`src/clients/base.py`

- 提供 `http_post` / `http_get` 方法，封装重试与日志
- 固定 3 次重试（`DEFAULT_RETRIES = 3`）
- 失败时 `logger.error` 记录，重试耗尽后 `raise RuntimeError`
- 所有客户端（Jira/KB/AI/Diana）继承此基类

---

## 4. 错误处理规范

三层模式（自底向上）：

| 层级 | 策略 | 示例 |
|------|------|------|
| IO/基础设施层 | 记日志 + raise | `base.py` HTTP 重试耗尽 → `raise RuntimeError` |
| 流程编排层 | 单条失败不中断批量 | `pipeline.py` 单个 bugid 失败 → `status="failed"` 继续下一条 |
| CLI 入口层 | 顶层兜底 | `main.py` `sys.exit(1)` |

**约定**：
- HTTP 层：必须捕获异常、记日志，重试耗尽必须 raise，禁止吞异常
- Pipeline 层：失败结果必须含 `status="failed"` 和截断的 `error_msg`
- CLI 层：`main()` 是唯一允许 `sys.exit(1)` 的位置
- 文件 I/O：缺失资源 `raise FileNotFoundError` 并附带说明
- 参数校验：非法参数 `raise ValueError` 并给出期望格式
