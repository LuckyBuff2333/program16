[结果 2] WIKI 文档 [智能影像/哨兵模式(qnx).md]:
背景简介
哨兵模式qnx侧服务程序进程名neuro_mgr,目前主要负责中高风险检测，其中中风险通过IMU信号变化获取，高风险通过对应CAN信号获取。日志问题为哨兵是否正常启动以及是否有正确检测和发出对应风险项信号。
哨兵启动日志：
SentinelMode OnStartEvent|fsa client send request id:5524
表示接收到了启动信号，高风险有信号即触发，中风险需要收集30s数据计算开始触发
如果没有正常开启，一般为fsa连接异常，需检查libfsa日志，对应client名字为NeuroMgrClient
哨兵关闭日志：
SentinelMode OnStopEvent|fsa client send request id:5526
中风险触发日志：
detected medium risk|fsa client send request id:5528
中风险IMU信号无效日志：
SentinelMode IMUYawRtPriV value:1
SentinelMode IMULatAccPrimV value:1
SentinelMode IMUVertAccPrimV value:1
SentinelMode IMURollRtPriV value:1
SentinelMode IMULonAccPriV value:1
高风险触发日志：
SentinelMode Alarm status :3|fsa client send request id:5528

需注意如果没有启动信号，即使触发的对应风险也不会发出信号，对应日志为：
SentinelMode ignore risk:%d since event not start

## 第 4 轮 — LLM 响应

知识库提供了关键的正常流程对照。哨兵模式（QNX 侧 neuro_mgr）高风险触发链路为：`SentinelMode Alarm status :3` → `fsa client send request id:5528`。而 Android 侧 XVR Service 负责实际录制，文件损坏/0字节的典型异常特征是 `XVRService-VideoRecorder ... isExceed:true`（U盘写入超时）或 `XVRService-FileUtils sync` 异常。

但**当前日志数据源完全为空**，我无法验证任何一跳。让我最后确认一次是否有其他可用的日志入口（如模块活动汇总），以排除工具层面的数据源问题。
