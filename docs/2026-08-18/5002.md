# Bug 5002 日志分析报告

## 根因结论
订单导出缓存未释放导致JVM老年代内存泄漏，最终引发OOM重启。

## 问题触发时间
2026-08-11 14:32:02

## 关键日志依据
- 2026-08-11 14:20:33 [WARN] order-service - JVM 老年代使用率 91%，Full GC 耗时 1.8s，存在内存泄漏迹象
- 2026-08-11 14:30:41 [ERROR] order-service - Full GC 耗时 6.2s，老年代回收率不足 5%，堆内存持续增长无法回收
- 2026-08-11 14:31:55 [ERROR] order-service - 大对象缓存 OrderExportCache 持有 240 万条记录未释放，确认为内存泄漏点
- 2026-08-11 14:32:02 [ERROR] order-service - java.lang.OutOfMemoryError: Java heap space，进程触发 OOM 自动重启

## 分析步骤
1. 发现问题现象：服务运行过程中JVM老年代使用率持续攀升至91%，伴随Full GC频率显著上升及单次耗时增加，服务性能开始劣化。
2. 深入排查过程：结合GC日志趋势分析，发现Full GC耗时激增至6.2s且回收率不足5%，表明堆内存中存在大量无法被垃圾回收器清理的存活对象，内存已逼近物理极限。
3. 定位具体根因：日志明确捕获到`OrderExportCache`大对象缓存持有超240万条记录未释放，该缓存缺乏生命周期管理与容量控制，导致内存持续累积直至触发`java.lang.OutOfMemoryError`。
4. 修复措施或建议：立即重构缓存逻辑，增设最大容量限制与TTL过期淘汰策略，并在导出任务完成后强制清空引用；同步完善JVM内存监控大盘与Heap Dump自动抓取机制，实现内存异常早期拦截。
