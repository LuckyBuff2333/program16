# Bug BUG-5004 日志分析报告

## 根因结论
网关SSL证书过期导致TLS握手失败，引发全站API调用中断。

## 问题触发时间
2026-08-12 11:05:02（依据首条ERROR级别日志记录）

## 关键日志依据
- 2026-08-12 11:05:02 [ERROR] gateway - SSL 证书校验失败：certificate has expired，域名 api.example.com 证书已于 2026-08-12 00:00 过期
- 2026-08-12 11:05:04 [ERROR] gateway - HTTPS 请求批量握手失败，javax.net.ssl.SSLHandshakeException，客户端报 ERR_CERT_DATE_INVALID
- 2026-08-12 11:05:08 [ERROR] web-app - 全站 API 调用失败率 98%，根因为网关证书过期导致 TLS 握手失败
- 2026-08-12 11:10:44 [DEBUG] crontab - 证书巡检任务上次执行 2026-08-05，巡检周期 7 天，错过到期提醒

## 分析步骤
1. （第一步：发现的问题现象）11:04:50起网关TLS握手失败次数异常攀升，11:05:08监控显示全站API调用失败率飙升至98%，第三方支付回调同步中断进入重试队列。
2. （第二步：深入排查的过程）逐层追踪错误日志，确认核心异常为SSL证书校验失败及客户端ERR_CERT_DATE_INVALID；结合定时任务调试日志排查运维侧原因，发现证书巡检周期设为7天且上次执行于08-05，未能覆盖证书到期日。
3. （第三步：定位到的具体根因）api.example.com域名SSL证书已于当日00:00正式过期，因缺乏自动化续期与提前分级告警机制，导致网关HTTPS服务全面不可用，进而阻断所有上游业务流量。
4. （第四步：修复措施或建议）紧急部署新证书并完成网关重载（日志显示11:15:36恢复）；后续需将证书巡检周期缩短至3天，配置T-7/T-3多级告警；接入自动化证书管理工具实现无缝续期，避免人工遗漏。
