### ④ 根因分析与关键发现

- 🔴 **DownloadBtnView 在 ViewHolder 复用时未重置 gravity 属性**：`parseDownloadStatusInfo()` 方法仅处理下载状态和背景色设置，不涉及 `gravity`/`textAlignment` 重置逻辑，导致 ViewHolder 复用时保留了之前某个状态下的居右对齐样式。（L24151 L24280 L29329 L29337）

- 🟡 **DownloadBtnView 日志完全缺失 gravity 相关记录**：所有 DownloadBtnView 日志仅包含 `isFocused` 状态和背景色设置，没有任何 `gravity`/`textAlignment`/`setGravity` 相关输出，构成负向证据——说明数据绑定流程中未显式处理文字对齐。（L24151 L24280 L29329 L29337）

- 🔵 **操作序列和状态切换逻辑完全正常**：展开→收起→再展开三次 performClick 均被正确响应，下载状态和背景色切换无误，问题仅局限于布局属性管理。（L21373 L21463 L23868 L27086）

### ⑤ 修复建议

**代码级修复（推荐）：**

在 `DownloadBtnView` 的数据绑定方法（`parseDownloadStatusInfo()` 或 `onBindViewHolder()` 中对应调用处）显式重置文字对齐属性：

```Java
// 在 parseDownloadStatusInfo() 或 Adapter.onBindViewHolder() 中添加
button.setGravity(Gravity.CENTER);
// 或
button.setTextAlignment(TEXT_ALIGNMENT_CENTER);
```

**排查方向：**

1. 检查 `DownloadBtnView` 布局 XML 中 `android:gravity` 或 `android:textAlignment` 的默认值是否为 `center`

2. 排查是否有其他下载状态（如「已下载」「更新中」）使用了不同的 gravity 设置，导致 ViewHolder 复用时样式污染

3. 使用 Layout Inspector 复现 Bug 时检查 DownloadBtnView 的实际 gravity 属性值，确认异常来源
