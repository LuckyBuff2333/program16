# Bug 5002 日志分析报告

## 根因结论
订单导出任务缓存未释放导致老年代内存泄漏，最终引发OOM重启。

## 问题触发时间
2026-08-11 14:32:02（OOM崩溃精确时间点）

## 关键日志依据
- 2026-08-11 14:05:18 [INFO] order-service - 订单导出任务开始，批次 batch-20260811-03
- 2026-08-11 14:30:41 [ERROR] order-service - Full GC 耗时 6.2s，老年代回收率不足 5%，堆内存持续增长无法回收
- 2026-08-11 14:31:55 [ERROR] order-service - 大对象缓存 OrderExportCache 持有 240 万条记录未释放，确认为内存泄漏点
- 2026-08-11 14:32:02 [ERROR] order-service - java.lang.OutOfMemoryError: Java heap space，进程触发 OOM 自动重启

## 分析步骤
1. 发现现象：订单导出任务执行后，JVM老年代使用率从82%快速攀升至91%，Full GC频率与耗时显著增加，随后服务抛出OOM错误并触发K8s Pod自动重启。
2. 深入排查：沿时间轴串联日志，确认内存异常起始于14:05的导出任务；通过观察GC日志趋势，发现老年代回收率极低（<5%）且堆内存呈单向增长，符合典型内存泄漏特征。
3. 定位根因：日志明确指向大对象缓存 `OrderExportCache` 在任务结束后未执行清理操作，持续驻留240万条记录，直接耗尽Java堆空间导致进程崩溃。
4. 修复建议：修复代码中的缓存生命周期管理，确保导出任务完成后立即清空或设置合理TTL；针对大批量数据导出改用流式/分页处理降低单次内存峰值，并补充堆内存与Full GC阈值的P1级监控告警。
