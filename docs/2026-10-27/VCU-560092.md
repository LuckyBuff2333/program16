# 背景

常见定位问题从表现形式上来讲包含车标**漂移**、**超前**、**滞后**、**卡顿**、**抖动**、**静止**，从根因上来讲主要分为几类：**GPS信号异常**、**IMU数据异常**、**脉冲车速数据异常**。

文档中会详细说明这些情况出现的原因，以及对应的特征日志，方便后续快速定位问题根因。

# 问题类型

## GPS信号异常

GPS信号异常的情况多种多样，分析的时候需要需要从多个维度去排查，主要分为以下几类：

### GPS数据没有回调

GPS数据没有回调时会导致后端融合定位完全依赖于IMU、脉冲车速数据进行推断，从而出现偏航情况。

### **星历数据异常**

GPS定位的原理大致可以理解为：通过测量你（接收器）到至少4颗卫星的距离，然后通过几何学交汇确定你的精确位置。为什么是四颗的原因是三颗得出经度、纬度和海拔，利用第四颗卫星来算出时间，这样GPS接收器就能同时计算出你的精确三维位置和精确的时间。

#### 特征日志

**正常日志**

NaviApp_Position_Service: (PositionPackage.java:186) onSatelliteNum() -> onSatelliteNum: **10**

**异常日志**

NaviApp_Position_Service: (PositionPackage.java:186) onSatelliteNum() -> onSatelliteNum: **1**

#### 分析方法

如果GPS数据正常回调，可以查看搜星数据是否异常，当回调数据日志打印数量为1时，即可判断当前定位数据不准确，可以转ICM分析。

## 分析结论
- **根因**: 导航声音关闭按键的语义是"导航播报静音"（`setting_voice_mute` / `mBroadcastMode` / `NaviPackage.isMute()`），与系统 AudioManager 的媒体/系统音量是**两套完全独立的状态**。导航进程（PID 17712）在整个窗口内既不读取也不写入任何系统音频状态（`getStreamVolume/getStreamMute/setStreamVolume/setStreamMute` 全量零匹配），系统侧 `AS.AudioService` 也仅播放点击音效而无任何音量/静音变更。因此"不联动"是当前实现的**设计层面完全解耦**行为，而非同步失败或回调丢失。
- **因果链**: 用户点击导航声音按键 → 导航进程仅切换内部 `setting_voice_mute` 状态并更新卡片 UI/触发 TTS 提示 → 该状态通过 `mBroadcastMode` 广播给语音助手/仪表侧 → **从未调用任何 AudioManager 接口** → 系统声音状态保持不变 → 表现为"按键与系统声音不联动"。
- **关键证据**:
  - `SimpleCardWidgetProvider.java:414/430` `toggleNaviBroadcast()` 仅写 `setting_voice_mute` + 触发 TTS，无 AudioManager 调用
  - `SettingManager.java:91` `insertOrReplace key=setting_voice_mute`
