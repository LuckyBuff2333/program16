## 分析结论
- **根因**: 灯光设置界面（PID 5118，`com.patac.hmi.settings`）与 statusbar 灯光控制 overlay（PID 2503，SystemUI）是两套**独立实现**。两者写入完全相同的 property（`VIRTUAL_CONTROL_AUTO_HIGH_BEAM_REQUEST` 0x2140127c）和相同的值（val=1 打开 / val=2 关闭），信号下发链路完全正常；但 **toast 提示逻辑仅内置于 SystemUI 的 `BasePatacAutoHighBeamSignal` 类中（本地主动调用 `showToast`），设置界面的 `LightControllerManager.setAhbaStatus` 路径完全没有 toast 调用代码**，导致设置界面点击打开自动远光灯时无 toast 提示。这是纯 HMI 层功能缺失。

- **因果链**: 
  设置界面点击"打开自动远光灯" → `LightControllerManager.setAhbaStatus value=1` → `CarPropertyManager.setProperty 0x2140127c val=1` → GMVHAL 成功收到（信号链路正常）→ **但设置界面路径无 toast 调用代码** → 用户看不到 toast 提示 → 与 SystemUI overlay（`BasePatacAutoHighBeamSignal` 内置 `showToast`）表现不一致。

- **关键证据**: 
  1. SystemUI toast 文案：`16:19:38.317 【ToastDefaultLayout】textSize 28sp text 近光灯开启且手动远光灯、雾灯关闭时，可根据环境自动调节远光灯 mode 0`（PID 2503）
  2. SystemUI toast 与 property 写入同毫秒同 PID：`16:19:38.318 BasePatacAutoHighBeamSignal: setAutoHighBeamAssistStatus, isSelect = false`（PID 2503）
  3. 设置界面写 property 正常：`16:19:21.332 LightControllerManager: setAhbaStatus value = 1` → `CarPropertyManager: setProperty, propertyId: 0x2140127c, val: 1`（PID 5118）
  4. GMVHAL 确认收到：`16:19:21.444 GMVHAL: vhal_set Property: VIRTUAL_CONTROL_AUTO_HIGH_BEAM_REQUEST int32Values: 1`（PID 1396）
  5. **决定性负向证据**：全量 328 万行日志中，PID 5118 搜索 `Toast|toast|showToast|Popup|showAtLocation` 仅返回 2 条无关的 `FUN_CLOSE_POPUP`（UpdaterUtils 弹窗关闭），**零条自动远光灯 toast 调用**。
