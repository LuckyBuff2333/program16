# 日志分析会话复核与泛解析（log-review-pan-scan）

## 概述

三层能力，一条知识闭环链：**反查定位（机械）→ 会话复核（对账+挖缺口）→ 泛解析（素材提取）→ 按原则沉淀知识**。

分析过程（判读）是目标驱动深挖：只为回答本案问题，检索窗窄，没理由看的永远不会进知识。泛解析补无目标广扫，产出"系统怎么运转"的构成性知识素材。**素材必须经过知识沉淀原则过滤才能入库**——原则唯一正本在 `references/knowledge-principles.md`，本文件不重复其内容。

## 何时使用

- 用户给出 traceId / 链路 ID，要拉取、分析该会话 → 场景一
- 用户给出 traceId **且** 附带"我的结论是… / 问题出在 xx 模块 / 帮我复核这次分析对不对、缺什么知识"→ 场景二
- 场景二完成 **且** 缺口密集 **且** 用户明确指令"泛解析/沉淀这个域"→ 场景三（禁自发触发——泛解析成本不低，值不值得由用户拍板，判据见原则第 15 条）

## 环境要求

- python3 + `pip install -r requirements.txt`（requests）
- 泛解析 fetch 子命令：`curl` + 解包工具（`7z` 支持 rar/zip；`tar` 系统自带）——缺失时先安装（Linux：p7zip-full/p7zip-rar）
- 凭据走环境变量 `ADP_API_KEY` / `ADP_APP_ID`（或 `--env-file` 指向 .env 文件）；凭据不打印不落盘

## 第一阶段：反查定位（机械）

```bash
python3 scripts/record_lookup.py <traceid> [--env-file <.env>] [--app-id <id>]
```

- `trace_id` 是记录内嵌字段（32 位十六进制），**不是** record_id 也不是 session_id——平台接口无法直接按它查询，须拉记录全量匹配
- ID 形态自动识别：`rcd_` 前缀→record_id、UUID→session_id、32 位十六进制→trace_id；其他形态全字段包含匹配
- 多条命中全部列出，按 create_time 让用户确认（同一问题可能多次运行）

## 第二阶段：取证包导出（机械，场景二必做）

```bash
python3 scripts/record_lookup.py <traceid> --env-file <.env> --export <取证目录>
```

| 文件 | 内容 | 复核角色 |
|---|---|---|
| `record.json` | question（用户原始输入）+ answer（智能体最终结论全文）+ result（Token/延迟量化基线） | 结论侧 |
| `session_messages.txt` | 会话消息流：工具调用序列、检索动作、犹豫与自我修正、降级声明 | 过程侧 |

单轮 Agent 运行 100+ 条消息属正常（工具调用+返回各算一条）；消息流每条有截断，完整原文不在其中——需要原文时用第四阶段泛解析。

**复核还需用户的语义输入**（缺了先索取）：①人工结论（判定的根因，最好含分析过程）②人工认定的问题模块。

## 第三阶段：三问复核（判读方法）

通读结论侧与过程侧后逐问产出。**对账是双向的**：两边冲突时不默认谁对，回到过程证据裁决——智能体可能握有人工没有的反证。

### 第 1 问：模块对不对

提取智能体结论的归位模块（进程名/服务名/日志 TAG），与人工认定模块比对，四档裁决：**一致 / 词汇差异但同一实体**（如报单模块名 vs 进程包名——判"对"，标注为词汇映射缺口）/ **链条环节对但主模块错** / **错**。证据：结论断点行原文 + 过程侧消息编号。

### 第 2 问：根因对不对 / 方向对不对

提取智能体的根因链（现象→机制→决策点）与置信度，与人工结论比对，四档裁决：**一致 / 方向一致深度不足 / 部分偏移 / 错误**。人工结论含分析过程时逐环节比对。用过程侧证据复核智能体结论可靠性：反证检索做没做、降级声明了什么、犹豫点在哪。

### 第 3 问：知识缺口挖掘与价值评估

在过程侧扫描缺口信号：冷域降级声明 / 语义犹豫 / 语义靠猜 / 穷举检索 / 门禁重试 / 检索未命中后绕行。每条缺口四要素成档：**缺什么**（具体业务知识/数据）、**过程证据**（消息编号+原文）、**质量影响**（补齐后能否到达决策点/提升置信度）、**效率影响**（对照 record.json 的 Token/延迟基线，估算可省的检索轮次）。

## 第四阶段：泛解析（场景三，域定向广扫）

```bash
# 1) 下载登记 + 解包 + 语料概况（分卷 rar 传 part1 即可；自动跳过二进制/转储分区）
python3 scripts/pan_scan.py fetch --case-id <ID> --url <u1> [--url <u2>] [--root var]

# 2) 多关键词组扫描（关键词组取：复核缺口清单实体 + 报单结论用语 + 同族扩展）
python3 scripts/pan_scan.py scan --case-dir var/dl_<ID> \
    --kw "<正则组1>" --kw "<正则组2>" --out pan_materials.md
```

scan 每关键词组产出：命中计数 / TAG 分桶 top20（域实体全景）/ 数字归一化去重样本 topN（成功失败对照、消息形态全集）。

**素材 → 知识件**：必须按 `references/knowledge-principles.md` 的过滤流程执行（第六节附操作顺序）——尤其应有态三禁令与人工审核闸，素材清单直接入库=把个案观测和未确认猜测固化成事实。

## 知识沉淀原则（唯一正本引用）

本技能一切"沉淀知识"的动作受 `references/knowledge-principles.md` 约束（17 条 + 素材过滤流程），此处不重述内容。要点速记：知识库叙述系统正常运行的样子；个案发生了什么，归案例与待确认清单；入库动作即人工审核闸。

## 坑位速查

| # | 坑 | 规避 |
|---|---|---|
| 1 | 把 traceId 当 record_id 直接查接口，扫全窗口报"未找到" | 先用 record_lookup.py 反查——trace_id 只是记录内嵌字段 |
| 2 | 缓存陈旧导致刚产生的 traceId 反查未命中 | `--refresh` 强制重拉（缓存 TTL 1 小时） |
| 3 | 记录超多触发翻页保险丝漏扫 | `--days` 缩窗分次反查 |
| 4 | 把消息条数当用户对话轮数 | 单轮 Agent 运行的工具调用+返回各算一条 |
| 5 | 盲信人工结论，把复核做成"找智能体错在哪" | 对账双向：智能体的反证可能支持它推翻人工结论 |
| 6 | 复核只读结论不读过程消息流 | 知识缺口只藏在过程侧（犹豫/降级/穷举） |
| 7 | 缺人工结论/问题模块就开工 | 场景二两样语义输入缺一不可，先索取 |
| 8 | 复核完自发跑泛解析 | 触发判据（冷域+高频+缺口密集）由用户拍板 |
| 9 | 把素材清单直接当知识件入库 | 素材→知识件必须过 knowledge-principles.md 过滤流程 |
| 10 | 泛解析关键词只抄分析过程用过的词 | 分析检索面窄正是盲区来源——关键词应取缺口实体+报单用语+同族扩展 |
