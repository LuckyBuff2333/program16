2. 典型问题与排查路径

2.1 时间线点击无反应（未进入详情页）
TAG: MediasTimelineFragment, PictureDetailActivityTAG
- 观察日志：
  - 是否有 mediaAdapterThree onItemClick call...
  - 是否有 startPicDetailActivity:
- 排查步骤：
  1. 若无点击日志，检查 RecyclerView 点击事件是否被拦截或处于编辑状态。
  2. 若有点击日志但无 startPicDetailActivity，检查 DebouncingUtils.isValid 是否阻止了触发。
  3. 若 startPicDetailActivity 存在但页面未打开，检查 Intent 参数与启动上下文。
2.2 进入详情页但显示位置错误
TAG: PictureDetailActivityTAG
- 观察日志：
  - startPicDetailActivity index :X
- 排查步骤：
  1. 确认 filterList.indexOf(...) 的结果是否与 UI 点击位置一致。
  2. 排查 data 截断（范围限制 400）是否导致索引偏移。
2.3 进入详情页但 UI 状态异常
TAG: PictureDetailActivityTAG
- 观察日志：
  - getIsBigVideo:...
  - isBigToggleAnimate:...
  - mCurrentFragment?.isCorrupted : actionEnalbe ...
- 排查步骤：
  1. 若无 getIsBigVideo，检查对应 LiveData 是否更新。
  2. 若 isBigToggleAnimate 未触发，检查 isViewAnimating 是否阻断动画。
  3. 若 actionEnable 关闭，检查媒体是否被判定为受损。

## 分析结论
- **根因**: 损坏图片放大标识的置灰（`checkBoxSelector alpha: 0.5`）由 **DataRepository 数据刷新回调（albumsSetInfo batch updated）驱动**，而非 onBind 内基于 isBroken 同步设置。首次进入选择器时，数据刷新回调（17:40:10.268）**早于** View 绑定（onBind 17:40:10.323~10.344）完成，此时 View 尚未就绪，置灰逻辑无法作用到 View；而 onBind 分支虽拿到 isBroken=true（10.342），却不负责设置 alpha。因此首次进入时放大标识未置灰。用户进入预览或切换相册后，触发 DataRepository 再次 batch updated（53.123/55.648），此时 View 已绑定，alpha:0.5 才正确生效。
- **因果链**: 数据刷新回调早于 View 绑定完成 → 首次置灰逻辑在 View 未就绪时执行失效 → onBind 分支不负责 alpha 设置 → 首次进入放大标识未置灰 → 预览/切换相册触发再次数据刷新（View 已就绪）→ alpha:0.5 生效 → 标识置灰
- **关键证据**:
  - 首次绑定帧（10.323~10.344）有 `isBroken=true` 但**无** `checkBoxSelector alpha: 0.5`
  - 17:40:47.087 帧有 `isBroken=true` 但无 batch updated，也**无** alpha
  - 17:40:53.123 `albumsSetInfo: batch updated` → 53.127 `checkBoxSelector alpha: 0.5`（紧跟数据刷新）
  - 17:40:55.648 `batch updated` → 同帧 `alpha: 0.5`
  - 首次 batch updated（10.268）早于首次 onBind（10.323）
- **置信度**: medium-high（时序差异为直接日志证据；"回调在 View 未就绪时失效"的具体代码分支为推断，因 alpha 打印点无方法栈日志）
- **未确认项**:

  2. 首次 batch updated（10.268）时 View 是否确实未 attach（onAttachedToWindow 在 10.344，晚于 10.268，间接支持）
