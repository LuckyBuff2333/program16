## 分析结论
- **根因**: 壁纸从"动态壁纸(live_paper)"切换为"静态壁纸"时，Launcher 的 `ImagePagerAdapter.updateImagesSilent` 检测到数据源变化（`lists differ`），触发 ViewPager item 重建，导致承载壁纸的 SurfaceView（103820224/144519229，format=-2 半透明）被销毁并重建。重建期间（08.769→09.165，约 396ms）SurfaceView 处于 `has no frame` 无 buffer 状态，露出默认黑底；同时底层 PresentationActivity 的不透明 SurfaceView（201669543）在 09.718 出现 `setFrame result false` 未及时刷新，两层叠加导致左上角局部区域闪现黑色阴影。
- **因果链**: 动态→静态壁纸切换 → Adapter 数据源替换(lists differ) → ViewPager item 重建 → SurfaceView 销毁(08.769) → 重建期 has no frame 无 buffer(09.162) → 露出默认黑底 + 底层 SurfaceView setFrame 失败(09.718) → 左上角闪黑阴影
- **关键证据**: 
  - `ImagePagerAdapter.updateImagesSilent: lists differ, updating data`（08.740，动态→静态切换）
  - `SurfaceView: 103820224/144519229 notifySurfaceDestroyed + releaseSurfaces`（08.769/08.770）
  - `SurfaceView: 144519229 updateSurface: has no frame`（09.162/09.164，无 buffer 直接证据）
  - `SurfaceView: 103820224 requiresSurfaceControlCreation: visibleChanged true`（09.162）
  - `SurfaceView: 201669543 setFrame: left 0, top 0, right 2992, bottom 1299, result false`（09.718，底层刷新失败）
- **置信度**: high（SurfaceView 销毁重建导致无 buffer 空窗为核心机制，有直接日志）；"仅左上角局部"的精确叠加机制为 medium（setFrame result false 与两层叠加关系为推断）
- **未确认项**: 
  1. 为何黑块仅限"左上角"局部而非全屏——推测与两层 SurfaceView（不透明底层 + 半透明上层）叠加及左上角状态栏边界有关，但搜索工具已达上限（25 次）无法进一步验证
  2. 首帧 Bitmap 就绪（09.162）后精确 commit 到 surface 的时刻（框架层无显式日志）
  3. PID 11183 与 5517 的进程关系（PresentationActivity 独立进程 vs 主 Launcher 进程）未完全确认
- **建议排查方向**: 
  1. 优化壁纸切换逻辑：动态→静态切换时避免 ViewPager item 全量重建，改用平滑过渡（如保留旧 SurfaceView 直到新首帧就绪再切换，或使用双缓冲）
  2. 检查 `ImagePagerAdapter.updateImagesSilent` 的 `lists differ` 判定逻辑，避免不必要的 Adapter 数据替换
  3. 排查 PresentationActivity SurfaceView（201669543）`setFrame result false` 的原因，确保底层不透明 SurfaceView 在壁纸切换时及时刷新
  4. 考虑在 SurfaceView 重建空窗期设置与壁纸主色调一致的占位背景，避免露出默认黑底
