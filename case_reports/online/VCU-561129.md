## 分析结论

- **根因**: `MfcPatacCheckbox`（CommonWidget-0.7.4 自定义勾选框控件）的 **drawable state selector 选择逻辑缺陷**——在 `checked=false` 且 `pressed=false` 的正常状态下，控件仍选中了 pressed 背景 drawable，导致取消勾选后视觉停留在 Pressed 外观。**pressed 逻辑状态本身已正确复位**（决定性证据：每次点击 DOWN 时 View flags 均为 `V.E......` 无 P 位，证明两次点击之间 pressed 已被 setPressed(false) 清除），问题出在**视觉层 drawable 状态映射**，而非触摸事件或 pressed 状态残留。

- **因果链**: 
  1. 用户点击取消勾选 → 触摸链路正常（假设2排除）→ performClick 正常触发 → isChecked 正确切换为 false（逻辑正确）
  2. UP 后 setPressed(false) 正常执行（证据：下次 DOWN 时 flags 无 P）
  3. **但 MfcPatacCheckbox 的 drawable selector 在 checked=false + pressed=false 时错误匹配到 pressed 背景** → 视觉残留 Pressed
  4. 表现为 Bug 现象"取消勾选后显示 Pressed"

- **关键证据**:
  - `dispatchTouchEvent Action 0 to ...MfcPatacCheckbox{d312da V.E......}`（09:42:41.073）、`{d4aa918 V.E......}`（09:43:02.499）、`{955aa7a V.E......}`（09:43:40.638）——**每次 DOWN 时 flags 均无 P 位**，证明 pressed 逻辑状态在点击间已复位

  - 对照组 `PatacRealButton`/`ConstraintLayout` 均有 Action 0（无 P）→ Action 1（有 P）完整日志，而 **MfcPatacCheckbox 仅有 Action 0 日志、无 Action 1**，说明其重写了 dispatchTouchEvent，pressed 视觉走自定义 drawable 路径
