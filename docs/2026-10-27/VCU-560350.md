# 背景

常见定位问题从表现形式上来讲包含车标**漂移**、**超前**、**滞后**、**卡顿**、**抖动**、**静止**，从根因上来讲主要分为几类：**GPS信号异常**、**IMU数据异常**、**脉冲车速数据异常**。

文档中会详细说明这些情况出现的原因，以及对应的特征日志，方便后续快速定位问题根因。

# 问题类型

## GPS信号异常

GPS信号异常的情况多种多样，分析的时候需要需要从多个维度去排查，主要分为以下几类：

### GPS数据没有回调

GPS数据没有回调时会导致后端融合定位完全依赖于IMU、脉冲车速数据进行推断，从而出现偏航情况。

#### **特征日志**

```
Bosch_NavSensors: LocationData: [31.255856, 121.655731, 52.800000, 21.660000, 93.820000, 0.000000, 0.100000, 0.270000, 0.000000, 1763387339580, 0x000000ff]
```

31.255856--->纬度，121.655731---->经度，52.800000---->海拔，21.660000---->GPS车速（单位m/s），93.820000---->方向，关注这几个关键数据即可。

```
com.sgm.hmi.sr-SRLocationManager: onLocationChanged location : Location[gps 31.255856,121.655731 hAcc=0.0 et=+11h20m46s457ms alt=52.8 vAcc=0.1 vel=21.66 sAcc=0.27 bear=93.82 bAcc=0.0 {Bundle[{satellites=0, maxCn0=0, meanCn0=0}]}]
```

```
NaviApp_Position_Service: (GnssManager.java:164) onLocationChanged() -> 原生 onLocationChanged ：当前位置信息:,精度:121.655731,纬度:31.255856,高度:52.8,速度:21.66,方向:93.82,定位精度:0.0
```

当日志当中不包含**Bosch_NavSensors**定位日志打印时，分析到这里就可以结束了，转给FWK分析GPS数据没有回调的原因即可。

当日志当中包含**Bosch_NavSensors**定位日志打印，仅导航进程没有收到定位回调数据时，需要查看**bugreport**日志当中**GNSS_HandlerThread**线程是否存活，如果没有下列类似堆栈打印，即说明定位线程异常退出后，导致系统定位数据无法进行分发导致的异常。

#### 分析方法

先查找是否包含**Bosch_NavSensors: LocationData** GPS数据是否有打印，有打印再去查看导航进程是否有重试相关日志打印，以及提醒用户查看**GNSS_HandlerThread**线程是否存活。

### **星历数据异常**

GPS定位的原理大致可以理解为：通过测量你（接收器）到至少4颗卫星的距离，然后通过几何学交汇确定你的精确位置。为什么是四颗的原因是三颗得出经度、纬度和海拔，利用第四颗卫星来算出时间，这样GPS接收器就能同时计算出你的精确三维位置和精确的时间。

#### 特征日志

**正常日志**

NaviApp_Position_Service: (PositionPackage.java:186) onSatelliteNum() -> onSatelliteNum: **10**

**异常日志**

NaviApp_Position_Service: (PositionPackage.java:186) onSatelliteNum() -> onSatelliteNum: **1**

#### 分析方法

如果GPS数据正常回调，可以查看搜星数据是否异常，当回调数据日志打印数量为1时，即可判断当前定位数据不准确，可以转ICM分析。

### GPS数据中车速和脉冲车速信号差距过大

当脉冲车速和GPS车速相差过大时，会导致全场景的定位问题，特别是在多圈环岛绕行、分叉隧道推算、地下停车行驶以及持续低速行驶等情况下，容易出现滞后、漂移等问题。

# 总结

定位问题的原因多种多样，需要针对具体问题具体分析。查看日志排查问题时的顺序按照如下顺序进行排查： 
1.[检查GPS数据是否正常回调]

2.[检查星历数据是否异常]

3.[检查GPS车速与脉冲车速差值是否过大]

4.[检查GPS数据上报频率是否异常]

5.[检查IMU数据是否异常]

6.[检查脉冲车速数据是否存在异常]

注：严格按照问题排查顺序来进行排查，当出现一个前置的问题后，后续的问题则不需要再进行分析，即分析到前置问题为止
