# Bug BUG-5005 日志分析报告

## 根因结论
定时报表慢SQL未命中索引引发全表扫描锁表，导致下游业务线程阻塞与服务雪崩。

## 问题触发时间
2026-08-13 16:20:04（日志首次明确记录“触发锁表”报错的时间点）

## 关键日志依据
- 2026-08-13 16:18:42 [WARN] report-service - SQL 执行耗时 8.3s，语句 SELECT * FROM t_trade_record WHERE create_time > '2026-01-01'，未命中索引
- 2026-08-13 16:20:04 [ERROR] report-service - 慢SQL全表扫描 1200 万行并持有表锁，执行耗时 56s，触发锁表
- 2026-08-13 16:20:08 [ERROR] order-service - 业务线程阻塞堆积：等待 t_trade_record 行锁的线程达 210 个，线程池使用率 100%
- 2026-08-13 16:20:15 [ERROR] gateway - 下游接口 /api/trade/query 超时率 92%，根因为慢SQL锁表导致业务线程阻塞

## 分析步骤
1. 发现问题现象：网关与支付服务日志显示下游交易查询接口超时率骤升至92%，订单服务线程池使用率达100%，系统出现严重响应延迟与自动降级。
2. 深入排查的过程：向上游追溯日志，发现db-monitor在16:19:36已报警表锁等待数持续增长；结合report-service日志，确认是16:18:42发起的报表查询SQL耗时异常且提示未命中索引。
3. 定位到的具体根因：报表导出任务执行的SQL语句缺乏有效索引，导致对千万级数据表进行全表扫描并长时间持有表锁，直接阻塞了所有并发访问该表的交易查询业务线程。
4. 修复措施或建议：DBA紧急Kill慢查询会话并补充`create_time`字段索引，服务于16:35恢复正常；后续需将报表大查询拆分至离线队列或低峰期执行，并上线慢SQL自动熔断与索引缺失巡检机制。
