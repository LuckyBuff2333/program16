## 第 2 轮 — 工具执行结果

[结果 1] WIKI 文档 [智能影像/360.md]:
1 背景
常见360全景影像问题从表现形式上来讲主要包含车模效果异常、错误码异常、障碍物距离异常、手动点击进入360异常。文档中会详细说明这些情况出现的原因以及对应的特征日志，方便快速定位具体原因。
2 问题类型
2.1 车模颜色异常
车模效果异常的表现形式多种多样，根本原因主要为是否收到正确的RPOcode以及是否将对应的kanzi车模颜色code发送到车模。
2.1.1 信号接收异常
未收到RPOcode或者未发送颜色code，导致车模没有收到对应的颜色，最终没有出现预期的结果。
日志TAG
SendCanValueToFC|rpoColorMap
特征日志
正常日志：
[SVMFsaProxy.cpp:186] svm get CarTintColor_event from android payloadLen:7, 5faf9bc4b0
[SVMFsaProxy.cpp:200] color_event RPO :GKT, id: 110
异常日志：
[SVMFsaProxy.cpp:195] Invalid color RPO :GZ9
分析方法
当出现车模颜色显示错误时，优先在gmlog查看是否从安卓收到颜色信号，如果同时存在color_event RPO和异常日志，则说明可能存在未适配的情况。

2.2 错误码异常
错误码异常的表现形式为显示0x开头的错误码，根本原因主要分为以下几种：
2.2.1 是否收到camera status
查看是否从camerastream接收camera status并正常设置。
日志TAG
SetCamStatus|camera status
特征日志
正常日志：

[CameraPpsHandler.cpp:94] On error, deviceId: 0, error: 0
[CameraPpsHandler.cpp:94] On error, deviceId: 1, error: 0
[CameraPpsHandler.cpp:94] On error, deviceId: 3, error: 0
[SVMInfoCenter.cpp:272] Set camera status, type:1, state:0
[SVMInfoCenter.cpp:272] Set camera status, type:0, state:0
[SVMInfoCenter.cpp:272] Set camera status, type:2, state:0
[SVMInfoCenter.cpp:272] Set camera status, type:3, state:0
分析方法
首先，在gmlog里面搜索是否收到错误码并设置了camera status，如果没有搜索到camera status，说明没有从camerastream接收到camera status。

2.2.2 是否把屏幕画黑
当进入360但是某一摄像头无效时，会把对应视图画黑覆盖。
