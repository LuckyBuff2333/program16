# Bug BUG-5001 日志分析报告

## 根因结论
慢查询长时间占用连接未释放导致连接池耗尽，引发订单服务批量超时。

## 问题触发时间
2026-08-10 09:15:01

## 关键日志依据
- 2026-08-10 09:15:01 [ERROR] order-service - 获取数据库连接超时（等待 5000ms），连接池已耗尽，active=50 idle=0
- 2026-08-10 09:15:03 [ERROR] order-service - java.sql.SQLTransientConnectionException: HikariPool-1 - Connection is not available, request timed out after 5000ms
- 2026-08-10 09:15:06 [ERROR] order-service - 下单接口 /api/order/create 批量超时，失败率 87%，根因指向数据库连接池耗尽
- 2026-08-10 09:25:33 [INFO] order-service - 慢查询扫描：SELECT * FROM t_order_detail WHERE status=0 执行耗时 28.4s，占用连接未释放

## 分析步骤
1. 发现问题现象：09:14:38起order-service日志记录数据库连接等待时间骤增，09:15:01起连接池彻底耗尽(active=50/idle=0)，导致下单接口批量超时且失败率飙升至87%。
2. 深入排查过程：追踪日志发现连接池活跃数已达上限且无空闲连接，随后user-service在09:18:22也出现连接等待变长，表明资源争抢已扩散至关联服务；结合09:16:40的P1级告警推送确认故障影响面扩大。
3. 定位具体根因：通过09:25:33的慢查询扫描日志精准锁定一条执行耗时28.4s的SQL语句，该查询因全表扫描或逻辑缺陷长时间持有数据库连接且未正常释放，直接抽干HikariCP连接池。
4. 修复措施或建议：立即优化目标SQL（补充状态索引或改为分页/条件过滤），调整HikariCP核心参数（缩短maxLifetime、启用leakDetectionThreshold检测连接泄漏），部署慢查询自动熔断与Kill机制，并建立连接池水位与响应时间的实时大盘监控。
