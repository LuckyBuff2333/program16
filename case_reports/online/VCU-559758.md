## 分析结论
- **根因**: 桌面车模（CHARGING 场景）并非由桌面 Launcher 自身渲染，而是由**设置应用进程（com.patac.hmi.settings）内的 KanziOneShotSurfaceView 渲染**，桌面通过 **RemoteCarTaskView（TaskView）嵌入**该 Surface 显示。杀掉设置应用后，其 LauncherActivity 被销毁 → `KanziOneShotSurfaceView.doReleaseSurface` 释放车模 Surface → TaskView `onTaskVanished reparent to null`（车模图层从桌面移除）→ 系统重建新 Task 时，Kanzi 服务 `relateSurfaceControlInner1` 关联 CHARGING 场景 Surface **连续两次 ###Fatal### 失败**（且 `main screen app id = 4`、`sceneName = Unable to determine`），导致车模无法立即重新渲染，形成约 1 秒以上的黑屏/车模消失闪现。

- **因果链**: 杀设置应用 → LauncherActivity 销毁 → Kanzi SurfaceView 释放车模 Surface（doReleaseSurface）→ TaskView onTaskVanished reparent to null（桌面车模消失）→ 新 Task 重建 → Kanzi relateSurfaceControlInner1 关联 CHARGING Surface Fatal 失败 ×2 → 车模渲染中断 ≥1s → 黑屏闪现

- **关键证据**:
  - `14:13:56.686 KANZI_SDK: KanziOneShotSurfaceView: doReleaseSurface unregisterListener`（PID 3896）
  - `14:13:56.791 TaskViewTaskController: wm_ onTaskVanished taskLeash:Surface(name=Task=1000236) reparent to null`（PID 2479）
  - `14:13:56.857 / 14:13:57.729 KANZI_SERVICE: ###Fatal###:relateSurfaceControlInner1 Surface(name=SurfaceView[...LauncherActivity]) sceneName:CHARGING ... mcurrentAppId = 4`（PID 4150）
  - `14:13:56.805/824 KANZI_SERVICE: ###Fatal###:main screen app id = 4`
  - `14:13:56.824 KANZI_SERVICE: KanziDataSource:setValue: sceneName = Unable to determine using sceneName`
  - `14:13:56.880 RemoteCarTaskViewServerImpl: Cannot apply null or empty insets`

- **置信度**: **high**（Surface 释放、TaskView reparent to null、Kanzi Fatal 关联失败三条直接日志证据完整闭合，时序一致）

- **未确认项**:
  1. 车模最终恢复的确切时间点（分析窗口内未搜到 Kanzi 成功关联 Surface 的日志，可能恢复日志未打或恢复发生在窗口外）
  2. `mcurrentAppId = 4` 的具体含义（Kanzi 内部 app id 映射，非 SDV 模块，知识库无定义）
  3. `relateSurfaceControlInner1` Fatal 的具体触发条件（Kanzi 引擎内部逻辑，需 Kanzi 侧确认为何新 Surface 关联失败）

- **建议排查方向**:
  1. **架构层面**：桌面车模依赖设置应用进程渲染 + TaskView 嵌入，这种跨进程 Surface 依赖在杀进程时必然出现空窗。建议评估是否应将 CHARGING 车模渲染迁移到独立常驻进程或桌面自身进程，避免杀设置应用影响桌面车模。
  2. **Kanzi 侧**：排查 `relateSurfaceControlInner1` 为何在 TaskView 重建新 Surface 时连续 Fatal 失败（`main screen app id = 4` 异常、`sceneName = Unable to determine`），确认 Kanzi 服务对 Surface 重建的容错/重试机制。
  3. **TaskView 侧**：`RemoteCarTaskViewServerImpl: Cannot apply null or empty insets` 告警需确认是否影响 TaskView 重建时序。
